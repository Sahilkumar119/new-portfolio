Kubernetes,
the 20% that runs 80% of your work

Kubernetes has hundreds of objects. You will use about fifteen of them, nearly every day. This course teaches only those: pods, deployments, services, ingress, config, secrets, storage, and the debugging playbook that turns a red CrashLoopBackOff into a fixed deploy in two minutes.

How to read this course

Work the modules in order. Each one assumes the last. Reading is not enough: keep a local cluster open in a second terminal and run every command, predicting the output before you press enter. Kubernetes only becomes intuitive once you have watched the reconciliation loop fight you a few times.

Prerequisite

You need working Docker knowledge first: images, containers, ports, volumes, and what a Dockerfile does. Kubernetes schedules containers, it does not teach you what one is. If any of that is shaky, run the Docker course first, then come back.

What is deliberately not here

Operators and CRDs, service meshes, custom schedulers, cluster installation from scratch, CNI internals, and the full API surface. All real, all rare. They are the other 80% of Kubernetes that accounts for 20% of the work, and every one of them is easier to learn once the objects in these eight modules are automatic.
